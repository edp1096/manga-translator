사용 방법과 동작 범위
패널의 인물 사전에서 작품별 풀네임·성·이름·별칭·확인한 읽기를 관리한다.
성·이름 구분 제안은 입력한 확정 표기를 바꾸지 않는 제안이며, 저장한 내용만 적용된다.
새 번역에는 현재 작품의 사전이 자동으로 전달된다. 검증을 통과하지 못한 번역은 성공으로 덮어쓰지 않는다.
기존 번역은 이름 통일 버튼으로 교정한다. 체크박스 선택과 관계없이 현재 작품의 불러온 결과와
확장에 남아 있는 같은 작품의 다른 화 캐시를 처리한다. 기존 캐시의 24시간 유효기간은 그대로다.
이미지 검출·OCR을 다시 실행하지 않고 번역 문자열을 교정한 뒤 기존 표시 모드로 배치를 다시 계산한다.
이름 되돌림은 교정 직전 이름을 복원한다. 교정 후 사용자가 직접 수정한 문장은 유지한다.
사전 변경·수동 편집·취소·엔진 사용 중 등의 상황에서는 이전 결과를 보호하며 재시도할 수 있다.
다른 작품에는 적용하지 않는다. 일반적인 chapter/episode 주소, ComicWalker 작품 경로,
Mangaz 작품 번호는 같은 작품으로 묶는다. 작품을 URL로 구분할 수 없는 뷰어는
다음 화에서 기존 작품을 선택하고 현재 주소를 연결해야 한다. Tonari 개별 episode 주소도 여기에 해당한다.
작품 사전을 JSON으로 내보내고 가져올 수 있다. 가져오기만으로 다른 작품의 연결을 자동 덮어쓰지 않는다.

후리가나와 불확실성
현재 서버의 Hayai ONNX OCR로 작은 후리가나 영역을 분리하여 읽는 보조 기능을 추가했다.
19페이지의 てんまのぞみ는 읽었다. 2페이지는 ほんごうひんな로 오독했고, 1페이지는 후보를 찾지 못했다.
따라서 후리가나 제안은 확인 없이 확정 표기를 바꾸지 않는다. 원본 확대 보기를 함께 제공한다.
2페이지 원본의 ほんごう / ひな를 직접 확인해 혼고 히나를 등록했다.
짧은 한자 이름은 문장 속 해당 위치마다 이름인지 일반 단어인지 판단한다.
실측: 希望を捨てないで。의 希望는 희망으로 유지했고, 사람을 부르는 希望는 노조미로 교정했다.
希望は最後の希望だ。에서는 노조미는 마지막 희망이야.로 교정했다.
판단이 불확실하면 강제 치환하지 않고 확인 필요 상태를 남긴다. 향후 모든 OCR·문맥 판단의 정확성을 보장하지 않는다.

검증 결과
실제 Windows Edge 156.0.4314.42를 띄우고 확장 도구 모음·설정·패널·편집기를 조작했다.
사전 UI 저장, 실제 Gemma 성·이름 제안, JSON 내보내기/가져오기, 후리가나 제안, 작품 분리를 확인했다.
샘플 20페이지 전체를 교정·내보내기·육안 검토했다. 11영역을 바꿨고, 같은 작품의 별도 캐시 1영역도 교정했다.
되돌림·재적용·새로고침·탭 복귀·편집기/PNG의 픽셀 일치·사전을 전달한 19페이지 새 번역을 확인했다.
17페이지의 장식 글씨는 기존 효과음/툴팁 표시 방식을 유지하며 번역 문자열만 교정한다.
7페이지의 이름 이외 기존 오역은 이름 교정 과정에서 임의로 다시 쓰지 않았다.
Chromium 147 및 Edge 156에서 취소·409 재시도·편집 충돌·캐시 복원 테스트를 통과했다.
기존 말풍선 배치 52건, 툴팁 접근 8건, 흰 배경 편집기 6건과 패널 표시·복원·재번역 회귀 검사를 통과했다.
사전이 없는 새 이미지 번역도 정상 완료했고, 인증 누락 401·잘못된 요청 400·엔진 사용 중 409를 확인했다.
Go 전체 테스트를 통과했고 관리 앱은 CGO_ENABLED=0, Windows GUI subsystem으로 빌드했다.

실험 중 발견해 함께 수정한 Windows 오류
재번역 시작 시 status.json 교체가 Windows 파일 잠금으로 거부되어 엔진이 종료되는 현상을 재현했다.
짧은 파일 잠금에는 제한된 횟수로 재시도한다. 오류 상태 저장도 실패하는 경우 메모리에 실패를 보관하고
API가 해당 작업 오류를 응답하도록 하여 엔진 프로세스가 종료되지 않게 했다.
실제 Windows 파일 읽기 잠금을 강제로 걸어 일시 잠금 회복, 지속 잠금 오류 응답,
오류 저장 실패 후 엔진 생존 및 다음 새 번역 성공까지 검증했다.
