Manga LaMa / 일승천금 72화 / Windows 시험 완료 기록
2026-10-28

결론

Windows x64 네이티브 실행, CPU/DirectML/CUDA 비교, 원래 모델과의 대조,
Edge 실제 사이트 미리보기까지 완료했다. 4070 SUPER 12GB에서 이 512x512
복원 작업은 CPU로 모델 연산을 넘기지 않고 실행된다. 가장 빠르고 원래
모델과의 차이도 작은 경로는 이번 조건에서 DirectML이었다.

모델은 글자를 지우고 하늘, 옷, 톤, 집중선을 이어 그리는 데 활용 가능하다.
그러나 현재 시험용 자동 획 마스크는 글자와 흰 테두리를 자주 놓친다.
이 결과를 범용 자동 복원이 완성됐다는 증거로 사용하면 안 된다.

이번 완료 범위는 모델 시험이다. 확장의 자동 검출/번역/표시 파이프라인에
복원 기능을 연결하거나 배포하지 않았다. 기존 실행 파일, 번역 결과,
설정, 모델, 사용자의 브라우저 프로필은 수정하지 않았다.
OP5P는 사용자 지시대로 제외했다. ARM64 Linux와 x64 Linux의 네이티브
동작/속도는 이번 Windows 측정으로 대체할 수 없으며 아직 미검증이다.

시험 자료

원본: https://klz9.com/isshou-senkin-chapter-72.html
17개 만화 페이지를 실제 Edge에서 수집했다. Patreon 이미지는 제외했다.
원본 파일과 해시는 images/, results/chapter.json, verification.json에 있다.

평가 위치: 4p 3영역, 5p 1영역, 6p 2영역, 8p 2영역, 11p 1영역,
13p 2영역. 위치는 수동 평가 주석이며 실제 검출기 성능 측정이 아니다.
11영역 각각 사각형/자동 획 마스크 = 22개 조각을 비교했다.
추가로 모든 사각형에 동일하게 4px 여백을 준 11개 대조군을 실행했다.
페이지마다 다른 복원 코드나 특별한 예외 규칙을 만들지 않았다.

성능

CPU: AMD Ryzen 5 7500F, 6코어/12스레드. 추론 6스레드 사용.
GPU: NVIDIA GeForce RTX 4070 SUPER, DXGI 전용 메모리 11997 MiB.
드라이버: 32.0.16.1656. OS/드라이버 API로 확인했다.

고정 512x512 RGB 조각, 모델 세션 유지, 조각마다 예열 1회+측정 3회.
아래 값은 22개 조각별 측정 중앙값의 중앙값이다.

경로                     ORT       추론       세션 생성    첫 조각 첫 추론
CPU                      1.24.4    1400.3 ms    549.7 ms     1407.2 ms
CPU (CUDA와 같은 ORT)     1.31.0    1401.8 ms    519.9 ms     1189.7 ms
DirectML                 1.24.4      39.1 ms   2177.4 ms       57.8 ms
CUDA, 기본 TF32          1.31.0      49.2 ms    519.8 ms      414.9 ms
CUDA, TF32 비활성        1.31.0      59.4 ms    552.5 ms      409.8 ms

DirectML 추론은 CPU 1.24.4 대비 약 35.9배, CUDA TF32 비활성은 CPU 1.31
대비 약 23.6배 빠르다. 세션 생성 시간이 있으므로 실제 기능에 연결할 때
매 조각마다 모델을 다시 불러오지 않고 세션을 재사용해야 한다.

추론 시간은 OCR/번역/검출/자동 마스크 생성/원본 페이지 자르기/전체 페이지
합성을 포함하지 않는다. PNG 입력 준비 약 5ms, 합성/PNG 저장 약 21~26ms는
별도로 기록했다. 따라서 0.039초를 전체 페이지 번역 시간이라고 말할 수 없다.
다른 해상도, 다중 요청, 다른 작품의 처리 속도는 이 측정에 포함하지 않았다.

프로파일에서 DirectML은 융합된 DML 노드, CUDA는 Conv/MatMul 등 전부 CUDA
노드로 실행됐다. CPUExecutionProvider 모델 연산 이벤트는 0개였다.
GPU 입력/출력 전송과 호스트 메모리는 여전히 사용한다.

DXGI 추론 후 현재 프로세스 전용 GPU 메모리:
DirectML 약 1078 MiB, CUDA 기본 TF32 약 1206 MiB,
CUDA TF32 비활성 약 694 MiB. 이 값은 최고점이 아닌 추론 후 스냅샷이며
런타임 작업 공간/예약을 포함한다. CPU 폴백 여부는 별도의 ORT 프로파일로
검증했다. CPU 프로세스 RAM과 GPU VRAM을 혼동하지 않는다.

구현 및 정확성

Manga LaMa 원래 구조의 torch.fft를 동등한 직교 푸리에 행렬 연산으로
표현해 ONNX로 변환했다. 가중치는 FP32 그대로이고 양자화하지 않았다.
CUDA에 없는 ONNX DFT 연산을 CPU에서 실행하는 문제를 피하기 위한 변환이다.
고정 512 입력, 표준 ONNX Conv/MatMul 등만 사용한다. CUDA 전용 사용자 정의
커널이나 Python 연산자는 없다. 다른 입력 크기는 별도 변환/검증이 필요하다.

무작위 입력 변환 검증: 원래 FFT 대비 ONNX 최대 차이 4.95e-6.
실제 22개 만화 조각도 원래 PyTorch FFT 모델과 비교했다.
CPU/DirectML/CUDA TF32 비활성의 마스크 내부 8비트 RGB 차이는 최대 1/255.
첫 실제 조각의 전체 float 출력 최대 차이:
CPU 6.91e-6, DirectML 6.50e-6, CUDA TF32 비활성 8.88e-6.
CUDA 기본 TF32는 8비트 최대 4/255 차이로 별도 기록했다.
이는 복원 그림의 정답 정확도가 아니라 구현/수치 연산의 일치도이다.

복원 모델 출력은 반드시 마스크 내부에만 합성했다.
5개 실행 경로의 22조각씩, 추가 여백 대조군 11조각, 17개 페이지 합성에서
마스크 밖 변경 픽셀은 모두 0개였다. 겹치는 문맥 조각을 전체 덮어쓰기하지
않고 해당 마스크 픽셀만 원본 페이지에 합성했다.

육안 확인

4p: 하늘/천장 선, 바지 명암, 톤 위 글자가 제거됐다.
5~6p: 투명/반투명 또는 무늬 배경 말풍선에서 바탕을 유지하며 제거됐다.
8p: 집중선 및 머리카락 주변 글자는 제거되지만 선 밀도/방향의 변화에 주의.
11p: 글자는 제거되지만 빛과 선화가 새로 그려져 원본 그대로라고 볼 수 없다.
13p: 기본 사각형 우측에 남던 흰 테두리는 공통 4px 여백으로 제거됐다.

자동 획 마스크는 흰 배경 선과 글자 테두리의 연결을 잘못 처리해 여러 영역에
잔상을 남겼다. 사각형 대조군은 글자를 더 안정적으로 지우지만 배경도 넓게
재생성한다. 여백 4px는 이 720x1020 샘플의 진단용 고정값이며, 다양한 원본
해상도/폰트/후리가나에 보편적으로 충분하다고 검증된 값은 아니다.
깨끗한 원래 배경의 정답 이미지가 없으므로 원본 복구 PSNR 같은 수치는 없다.

브라우저

실제 Windows Edge, 별도 임시 프로필, headless=false.
review.html의 전체 비교 조합과 17개 페이지, 원본/복원 버튼, 마스크 표시,
슬라이더 전환을 테스트했다. 최종 조합 99개: 11영역 x (여백 DML 1개 +
사각형/획 마스크 각각 CPU/DML/CUDA TF32 on/off 4개).
실제 사이트에서도 4/6/11/13p를 표시해 화면을 저장하고 육안 확인했다.
6개 대상 페이지의 원본 복귀/복원 재표시를 3회 반복 검증했다.

실제 사이트의 광고 클릭 가로채기를 피하도록 시험 버튼만 별도 iframe에
넣었다. 원본 문서는 사이트에서 로드하고 이미지는 보존한 같은 원본으로
응답했다. 이것은 DOM에 임시 적용한 복원 미리보기이지, 확장 기능 통합
테스트가 아니다. 실패했던 초기 미리보기 캡처 대신 최종 성공 캡처가 있다.
results/browser-checks.json, browser-gallery-final.json, edge-live-*.png 참조.

재현

눈으로 비교: 같은 폴더의 review.html을 Edge로 연다.
전체 비교 이미지: results/quality-all-masks.jpg
실행 패키지: D:\dev\pcbangstudio\workspace\manga-translator\data\experiments\manga-lama-windows
GPU: RUN-DIRECTML.cmd / CPU: RUN-CPU.cmd
결과: 패키지의 outputs/ 아래. 실행 시 Python 설치/호출이 필요 없다.
모델/ONNX Runtime/DirectML DLL/fixture를 포함한 약 238 MiB 독립 시험 폴더다.
프로세스 로드 모듈도 확인했다. Python 모듈 0개이며 패키지 밖 Python 설치
경로를 참조하지 않는다. 패키지 위치에서 native EXE 실제 실행도 통과했다.

CUDA 시험 런타임은 C:\Users\swshi\AppData\Local\Temp\manga-lama-ch72 아래다.
CUDA DLL은 기존 설치에서 네이티브 DLL만 복사해 분리했다. Python 인터프리터는
복사/실행하지 않았다. 최초 CUDA 12.6 cudart의 누락 API 오류는 시험 폴더만
공식 CUDA 12.8.90 cudart로 교체해 해결했다. Windows 전역 설치는 변경하지 않았다.
CUDA 설정/의존성 해시/프로파일은 results/에 보존했다.

빌드용 도구는 Python을 사용했다. /tmp/manga-inpaint-dev의 변환/검증 환경은
배포 런타임이 아니다. 사용자 요구인 Python 없는 추론 실행과 구분한다.
컨트롤러는 변경하지 않아 CGO_ENABLED=0 조건에도 영향을 주지 않았다.

네이티브 시험 빌드(프로젝트 루트):
x86_64-w64-mingw32-g++-posix -O2 -std=c++17 -static -DNOMINMAX
  -D_WIN32_WINNT=0x0A00 -I native -I /tmp/manga-bubble-probe/sdk/ort/include
  docs/manga-lama-ch72-2026-10-28/tools/benchmark.cpp -lpsapi -ldxgi
  -o benchmark.exe
위 명령은 실제 실행 시 한 줄로 연결한다. 설정 JSON 경로를 EXE 첫 인자로 준다.
JSON의 상대 경로는 현재 디렉터리가 아니라 JSON이 있는 폴더 기준으로 해석한다.

이후 제품 통합에서 해결할 항목

1. 기존 검출/OCR 결과로 글자·흰 테두리·후리가나를 빠짐없이 마스킹할 것.
   테스트의 수동 위치 주석을 자동 검출 성능으로 오인하지 않을 것.
2. 마스크 신뢰도가 낮거나 선화 훼손이 큰 경우 기존 툴팁/흰 배경으로
   돌아갈 수 있게 원본, 마스크, 복원 결과를 분리 보존할 것.
3. 반복 사용 세션, 조각 문맥/경계, 캐시 키, 취소/오류 처리, 패널 즉시 전환을
   연결한 뒤 새로운 작품과 해상도에서도 실제 확장 동작을 검증할 것.
4. OP5P 전원이 켜진 뒤 Windows 변경을 명시적으로 가져가 ARM64 CPU와
   x64 Linux를 따로 빌드/실측할 것. 보조 호스트의 오래된 사본으로 덮지 말 것.
