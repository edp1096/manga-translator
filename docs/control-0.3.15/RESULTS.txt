0.3.15 — reader navigation reliability and no completion jump

Requested behavior:
Refresh/preload and translation completion no longer restore their starting
page or scroll position. A reader location selected during translation stays
selected when the batch finishes. ZIP export still restores its own bookmark.

Navigation:
- Retry an ignored keyboard/click request within a bounded 20-second budget.
- Check actual progress before retrying; avoid duplicate inputs during a
  running carousel animation or while Mangaz has accepted a page change.
- Wait while the manga document is hidden. Hidden time does not consume the
  page-ready timeout. Show a resume message and allow cancellation.
- Mangaz uses the viewer's displayed page counter as its current position and
  the semantic next/previous controls for its reading direction.
- If Mangaz reports the target page but its image remains hidden after a late
  paired-page load, use its existing public resize handler to redraw it.
  No private viewer function, image decryption, or access-control bypass.

Observed failure:
The public Mangaz book 287048 reproduced a first-page navigation timeout on a
reverse pass: URL i:0 and counter 1, while image 0 had a zero-sized rectangle
and image 1 remained visible. Inferring the current page from visible images
made the old adapter repeatedly move backward past the first page. The new
counter-based detection and public redraw resolves this observed condition.

Verification:
- Real Kadocomi user-supplied episode: all 18 pages read horizontally.
- Real reader integration: Kadocomi 18 (horizontal samples and full vertical
  reading), Tonari 38, Mangaz 7; no reading failures, aligned overlays,
  results retained, no forced completion jump.
- Real Mangaz stress: 21 reads over three forward/reverse passes at 1100x800
  and devicePixelRatio 1.25, with 350ms image network delay and deliberately
  dropped clicks. All passed after the fix.
- Deterministic regression: old adapter fails after one dropped keyboard
  input; new adapter recovers. Slow accepted transitions do not skip pages.
  Hidden-document waiting/cancellation, slow Mangaz load, and the observed
  stale first-page image condition all passed.
- An API kept busy during translation allowed a locate command to finish
  before translation; completion preserved that selected page.
- Existing lazy-image loading, retry/resume, selections and ZIP tests passed.

Limits:
Reader integration uses real public viewer DOM/images, but translation API
responses are mocked and tainted-canvas screenshot pixels come from Playwright.
The user's intermittent Kadocomi failure was not reproduced naturally in an
isolated foreground session; it read all pages even before the change.
The retry path was proven with deterministic dropped input. Parallel native
translation was not established as the sole cause. Hidden state was exercised
in a controlled regression; no claim of a natural background-tab reproduction.
Windows Edge execution and its native sidebar limitation are not resolved by
this release. No user translation process was stopped for verification.
